# Security and privacy
Clipboard monitoring makes no network requests. AI is disabled by default; only the explicit Send button submits the displayed input to https://api.openai.com/v1/responses. Requests use store:false, a 24,000-character input cap, 2,048 output tokens and a 60-second timeout. OpenAI provider retention policies still apply. API model availability depends on the user's account.
API keys are written only to macOS Keychain. The settings field is secure and cleared after saving; keys are never loaded into preferences or logs. No telemetry or clipboard-content logging is implemented.
Source text is untrusted data, separated from the transformation instruction. No tools, code execution, shell interpolation, automatic uploads or generated-content execution exist. Prompt defenses are imperfect; the app's lack of execution capabilities is the security boundary. Review generated text for accuracy.
History uses atomic local JSON with owner-only permissions. It is not encrypted by the app. FileVault and OS account protections remain relevant. Persistence-off removes saved history; clearing removes entries. Corrupt/unknown-version files are preserved and writes stop until an explicit reset.
Concealed, transient and autogenerated pasteboard markers are excluded. Optional heuristics skip recognizable credentials, but cannot guarantee secret exclusion. Application exclusions use foreground bundle IDs, which are an approximation of source ownership. Pause monitoring for sensitive workflows.
Automatic paste requires Accessibility permission and rechecks destination focus before posting Command-V. It cannot prove the destination accepted the event and does not bypass secure input. Copy-only remains available.
No cross-device sync, cloud database or telemetry is enabled. Future synchronization requires authenticated encrypted transport and explicit configuration.
